# ADR 0001：单仓库与服务边界

状态：Accepted

## 背景

WoLinkup 同时包含多个前端、核心交易、供应商集成和财务能力。团队与交易规模尚未确定，过早强制独立微服务会增加本地开发、发布和故障排查成本，但把所有代码放进无边界单体又会使支付和供应商逻辑快速纠缠。

## 决策

采用 pnpm + Turborepo 的 TypeScript monorepo。代码按领域服务划分，每个服务拥有自己的 schema、接口和事件；早期允许合并部署，后续按吞吐、隔离、合规或团队所有权独立拆分。

## 结果

- 跨端契约和工具可统一版本，原子变更容易。
- 服务边界在代码和数据层可见，部署拓扑仍保持弹性。
- 必须通过依赖规则和评审防止跨目录直接访问内部实现。
- 非 TypeScript 的高价值组件未来可独立加入，不要求所有技术栈永久统一。

## 未选择

- 一开始建立大量独立仓库：跨契约变更和原型阶段维护成本过高。
- 单一应用加共享数据访问层：难以保护账务、供应商和交易边界。
