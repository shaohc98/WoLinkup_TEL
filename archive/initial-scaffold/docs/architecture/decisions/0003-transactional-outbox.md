# ADR 0003：事务 Outbox

状态：Accepted

## 背景

支付、订单、充值、通知和财务之间需要跨服务传播状态。直接在数据库提交后发布消息会产生“数据已写但消息丢失”，在发布后提交数据库又会产生“消息已发但事务回滚”。

## 决策

领域变更和 outbox 事件在同一数据库事务写入。发布器至少一次投递；消费者使用事件 ID 和 inbox 表去重。事件包含版本、aggregate、correlation 和 causation 信息。

## 结果

- 事件不会因进程崩溃永久丢失。
- 消费者必须幂等，事件顺序只能在聚合内通过版本处理。
- 需要监控 outbox 积压、发布失败和死信。
- 不承诺跨服务瞬时一致，用户体验需表达“处理中”。
