# 服务边界

状态：Draft

## 数据所有权

| 聚合/数据                              | 唯一写入方              | 读取方式                   |
| -------------------------------------- | ----------------------- | -------------------------- |
| 国家、号码规则、运营商、产品发布版     | business-service        | API 或发布事件构建只读视图 |
| 报价、订单、充值尝试、路由决策         | business-service        | 订单查询 API / 事件        |
| 供应商、SKU 映射、健康度、余额快照     | supplier-service        | 内部 API / 事件            |
| 支付、退款、账户、凭证、分录、对账     | payment-finance-service | 授权 API / 财务事件        |
| 客户运营、会员、优惠、内容、工单、权限 | operation-service       | API / 事件                 |
| 通知投递和 webhook 尝试                | notification-worker     | 运营查询 API               |

## 依赖方向

- 应用只调用 API gateway/BFF，不直接访问数据库。
- 业务服务调用供应商与支付服务的命令/查询 API。
- 支付服务不依赖订单内部表，只保存稳定的业务引用。
- 供应商服务不依赖消费者、会员或营销概念。
- 运营服务可以聚合只读数据，但不能成为订单或财务真相来源。
- 共享包不得访问数据库或网络，避免把服务耦合隐藏在工具包里。

## 允许的跨边界机制

| 场景             | 机制                  | 原因                       |
| ---------------- | --------------------- | -------------------------- |
| 创建支付意图     | 同步内部 API          | 用户正在等待，必须立即返回 |
| 支付捕获结果     | 事件 + 查询兜底       | 渠道回调异步且可能重复     |
| 获取候选供应 SKU | 同步内部 API + 短缓存 | 路由需要当下资格和余额     |
| 订单状态推送     | 事件                  | 多消费者、无需阻塞交易     |
| 管理台详情页     | API 聚合              | 需要实时授权与脱敏         |
| 分析报表         | CDC/事件到分析仓库    | 隔离生产负载               |

## 禁止模式

- 跨服务直接更新数据库表。
- 在 API gateway 写价格、路由或账务规则。
- 用缓存余额判断最终财务事实。
- 在消费者前端依赖供应商错误码。
- 通过共享数据库事务假装解决跨服务一致性。
- 未记录决策版本就动态改变历史订单的价格或路由解释。
