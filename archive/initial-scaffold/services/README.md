# 服务层

服务目录体现业务所有权，不强制每个目录从第一天就独立部署。初期可以共享发布单元，但数据库 schema、事件和内部 API 边界保持清晰。

| 服务                      | 所有数据                                     | 主要职责                                       |
| ------------------------- | -------------------------------------------- | ---------------------------------------------- |
| `business-service`        | 报价、订单、价格快照、充值尝试               | 目录查询、定价、订单状态机、履约编排和路由决策 |
| `supplier-service`        | 供应商、凭证引用、SKU 映射、余额与健康度     | 标准化上游差异，管理供应网络和适配器           |
| `payment-finance-service` | 支付、退款、账户、凭证、分录、对账           | 收付款、余额账户、双分录账本、结算与对账       |
| `operation-service`       | 客户运营、会员、营销、内容、工单、权限、审计 | 支撑后台运营和客户服务                         |
| `recharge-worker`         | 无独立业务真相                               | 消费 outbox、执行充值、查询和超时补偿          |
| `notification-worker`     | 通知任务和投递结果                           | 短信、邮件、推送、站内信和 webhook 投递        |

服务之间不得直接写入对方拥有的表。需要强一致时使用拥有方 API；可最终一致的传播使用事务 outbox 和幂等消费者。
