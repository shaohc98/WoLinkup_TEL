# 事件响应手册

状态：Draft

## 分级

| 级别  | 示例                                                      | 响应                                 |
| ----- | --------------------------------------------------------- | ------------------------------------ |
| SEV-1 | 重复扣款/充值、账本不平、大规模数据泄漏、交易全停         | 立即响应，冻结相关通道，建立指挥频道 |
| SEV-2 | 主要国家/供应商失败、退款大面积延迟、后台高风险功能不可用 | 15 分钟内响应，降级或切换通道        |
| SEV-3 | 局部功能退化、单一报表/通知异常                           | 工作时间响应，建立修复计划           |

## 通用流程

1. 确认影响：时间、渠道、国家、供应商、订单数、金额和客户表现。
2. 控制扩散：暂停路由/支付/发布，保留证据，不盲目重放未知订单。
3. 建立事实：使用 correlation ID 串联订单、支付、尝试、事件和账本。
4. 恢复服务：优先可逆配置和流量措施；数据修复使用审计命令。
5. 核对资金：订单恢复不代表账务完成，必须单独核对支付、退款和供应商结算。
6. 沟通：内部固定节奏更新；外部说明准确区分处理中、失败和退款。
7. 复盘：记录时间线、根因、促成因素、检测缺口、改进项和 owner。

## 禁止操作

- 未确认供应商终态就跨供应商重充。
- 直接修改生产订单或账本状态“解决”告警。
- 删除失败消息、回调原文或审计证据。
- 在公共聊天粘贴完整手机号、密钥或支付载荷。
- 把客户退款完成与内部问题修复混为同一个关闭条件。
