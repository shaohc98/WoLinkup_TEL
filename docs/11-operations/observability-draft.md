# 可观测性与 SLO

状态：Draft

## 关联标识

所有日志、trace 和事件传播 `correlation_id`。同时记录非敏感的 `order_id`、`payment_id`、`attempt_id`、`supplier_id` 和 `channel`。手机号只记录脱敏值或不可逆查找哈希，禁止记录原始请求体。

## 核心指标

### 业务

- 报价到下单、下单到支付、支付到充值成功的转化率。
- 按国家/运营商/供应商的成功率、退款率和毛利。
- 状态未知与人工复核数量、平均处理时长。
- 对账差异笔数、金额和关闭时长。

### 技术

- API RED：请求率、错误率、延迟。
- worker 队列深度、最老任务年龄、重试和死信。
- outbox 未发布数量与最老事件年龄。
- 数据库连接、锁等待、慢查询、复制延迟和磁盘。
- 第三方调用成功率、超时、限流、P95/P99 延迟和熔断状态。

## 初始 SLO 建议

- 订单查询月可用性 99.95%。
- 创建支付/订单月可用性 99.9%。
- 内部订单状态事件 99.9% 在 60 秒内发布。
- 99% 的明确供应商结果在 60 秒内反映到客户状态。

充值到账时间受供应商和运营商影响，应作为端到端业务 SLI 分层展示，不与平台 API 可用性混为一谈。正式目标需依据试运营基线调整。

## 告警原则

告警必须对应用户影响或即将耗尽的安全余量，并附仪表盘、runbook 和 owner。关键告警包括重复充值信号、账本不平、支付捕获未建订单、成功率突降、供应商余额不足、outbox 积压和退款失败。
