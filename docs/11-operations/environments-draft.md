# 环境、发布与回滚

状态：Draft

## 环境

| 环境        | 数据      | 外部系统               | 目的                |
| ----------- | --------- | ---------------------- | ------------------- |
| local       | 合成数据  | stub/sandbox           | 开发与单元/组件测试 |
| integration | 合成数据  | 供应商和支付 sandbox   | 契约与跨服务集成    |
| staging     | 脱敏/合成 | sandbox 或受控小额通道 | 发布候选验收和演练  |
| production  | 真实数据  | 生产通道               | 正式交易            |

环境账户、密钥、数据库和消息通道完全隔离。禁止把生产凭证放入非生产环境，也禁止直接复制生产 PII。

## 发布

- 主干开发，短分支，构建一次并逐环境提升同一不可变制品。
- 数据库使用向前兼容的 expand/migrate/contract 过程，迁移只追加。
- API 和事件先发布兼容生产者，再迁移消费者，最后移除旧字段。
- 高风险服务使用金丝雀或分批发布，按订单成功率、延迟、账务和错误预算自动暂停。
- 功能开关有 owner、过期时间和清理任务，不能长期替代版本控制。

## 回滚

应用回滚不得依赖回滚已执行的数据迁移。状态机、账本和事件修复使用补偿命令或新迁移。供应商/支付异常优先关闭路由或渠道，保留订单进入可恢复状态。

## 数据库

- 自动备份和时间点恢复，定期在隔离环境验证恢复时间与完整性。
- 账本、订单、支付和审计定义更长保留策略，具体期限由法律和财务确定。
- 大表按时间和访问模式分区，归档不破坏订单与凭证引用。
