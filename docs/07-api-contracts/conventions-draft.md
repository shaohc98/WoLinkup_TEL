# API 规范

状态：Draft

## 基础规则

- 公网 REST API 使用 `/api/v1` 路径版本；重大不兼容变更升主版本。
- JSON 字段使用 `camelCase`，时间使用带时区的 RFC 3339 UTC 字符串。
- ID 使用不可猜测标识；面向用户另设可读订单号，不能作为授权依据。
- 对外金额统一为十进制字符串加 ISO 4217 币种，例如 `{ amount: "100.00", currency: "CNY" }`；内部存储精度由数据设计约束。
- 电话号码进入服务后规范化为 E.164，响应默认只返回脱敏值。
- 每个请求接受/返回 `X-Correlation-Id`，日志和事件继续传播。

## 幂等

创建订单、支付、充值尝试、退款和后台高风险命令必须携带 `Idempotency-Key`。服务保存作用域、请求哈希和首次结果：

- 相同键和相同参数返回首次结果。
- 相同键但参数不同返回 `409 IDEMPOTENCY_CONFLICT`。
- 处理中返回同一资源和可查询状态，不并发执行第二次。
- 保留时间覆盖客户端、支付渠道和供应商的最大安全重试窗口。

## 错误

使用 `application/problem+json`，字段包括 `type`、`title`、`status`、`code`、`detail` 和 `correlationId`。`code` 是稳定机器码，展示文案由客户端本地化。验证错误可附带字段列表，但不回显密钥、完整号码或上游原始报文。

## 分页与筛选

- 高频变化列表使用游标分页：`pageSize`、`pageAfter`、`nextPageAfter`。
- 管理后台导出异步生成，返回任务 ID，不在同步请求中导出大文件。
- 时间范围必须指定时区语义，后台筛选上限由接口明确限制。

## 兼容性

- 可以新增可选字段和新枚举，但客户端必须对未知字段宽容。
- 新增枚举可能影响穷举代码，契约发布前需运行消费者契约测试。
- 删除/重命名字段、改变金额或时间语义属于破坏性变更。
- API 和事件分别版本化；内部模型不得直接序列化为公共响应。

经评审的 OpenAPI 3.1.1 契约发布在 `packages/api-contracts/openapi/`。当前不提交未经接口评审的占位契约。
