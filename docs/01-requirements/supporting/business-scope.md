# 产品愿景与范围

## 愿景

WoLinkup 将分散的全球话费供应网络统一为可信、可运营、可审计的充值基础设施，让消费者和企业客户用一致的方式完成跨国家、跨币种、跨运营商充值。

## 用户与价值

| 用户         | 核心目标           | WoLinkup 提供的价值                  |
| ------------ | ------------------ | ------------------------------------ |
| 国际消费者   | 为自己或亲友充值   | 本地化体验、多币种支付、订单可追踪   |
| 中国大陆用户 | 为海外号码充值     | 中文流程、人民币支付、清晰汇率和售后 |
| 运营人员     | 管理商品和异常订单 | 统一后台、状态追踪、可控人工干预     |
| 财务人员     | 核对业务资金事实   | 退款、供应商资金、对账与差异闭环     |
| 供应商运营   | 维护通道和价格     | 标准接入、SKU 映射、余额与 SLA 管理  |
| 客服人员     | 处理查询和申诉     | 订单全景、工单、通知记录和操作审计   |
| 企业客户     | 通过 API 批量充值  | 稳定契约、幂等、回调和用量结算       |

## 产品边界

首期包含移动预付费话费充值以及完成充值所需的支付平台集成、退款业务、供应商路由、财务事实、对账和运营能力。收银台、支付渠道、商户号、支付侧退款执行与结算属于独立 Payment Platform。

首期不默认包含流量包、礼品卡、水电煤缴费、贷款、数字货币结算或移动钱包转账。这些能力应在合规和供应链条件具备后作为独立产品类型接入，不能借用话费 SKU 语义硬扩展。

## 业务不变量

- 同一个客户端幂等键只能创建一个业务订单。
- 只有 Payment Platform 明确确认支付成功且通过风险门控，订单才能释放到履约。
- 每次充值尝试只能绑定一个供应商和一个供应商 SKU。
- 供应商成功终态不能因普通重试回退；冲正必须生成独立事件。
- 退款金额不得超过该支付单可退金额。
- 财务事实必须可追溯到订单、支付平台引用、履约尝试或退款订单。
- 商品发布必须引用有效的国家、运营商、币种和至少一条可用供应路由。
- 交易使用创建订单时保存的价格快照，后续调价不得改变历史订单。

## 成功指标

- 支付成功到充值成功的转化率。
- 各国家、运营商和供应商的成功率、P50/P95/P99 到账时长。
- 订单毛利与汇率偏差、退款率、人工处理率。
- 对账差异金额与平均关闭时长。
- 重复充值、重复扣款和不平账事件数量，目标为零。
