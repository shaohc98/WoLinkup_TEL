# 主数据治理

状态：Draft

## 受治理数据

国家/地区、国际区号、号码计划、运营商、运营商品牌、币种 exponent、产品面额、供应商 SKU、采购价、销售规则和汇率都影响交易结果，必须视为主数据，而非前端常量。

## 发布流程

1. 导入：保存原始来源、文件哈希、采集时间和解析结果。
2. 校验：检查 ISO 代码、E.164 规则、币种精度、重复实体和引用完整性。
3. 差异：生成新增、修改、停用清单，标记高风险变化。
4. 复核：产品/运营复核业务含义；价格与结算变更由财务复核。
5. 发布：生成不可变版本，设置生效时间并写审计事件。
6. 监控：观察识别率、失败率、毛利和供应商错误，支持快速回退到上一版本。

## 原型数据处置

`docs/02-product-design/prototypes/legacy/data` 的两份脚本规模相同但规则并不一致。导入器必须将二者标记为独立来源，输出逐字段差异，不能自动选择“更新的一份”。特别需要人工确认号码首位规则、去除 trunk prefix、运营商别名、强货币面额和汇率方向。

## 汇率

- 保存 base/quote、精确有理数或高精度 decimal、来源时间、抓取时间和过期时间。
- 报价锁定使用明确版本；过期报价必须重算。
- 展示汇率、计价汇率、会计汇率和供应商结算汇率可以不同，字段不得复用。
- 汇率偏差、陈旧数据和来源中断触发熔断或扩大风险缓冲，不静默使用无限期旧值。

## 数据质量指标

- 号码无法识别率、人工选择运营商比例。
- 商品无可用供应 SKU 数量、价格倒挂数量。
- 供应商 SKU 映射冲突和过期率。
- 汇率数据时效与异常变动。
- 发布后充值失败率相对基线变化。
