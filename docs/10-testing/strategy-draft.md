# 测试策略

状态：Draft

## 测试分层

| 层级       | 目标                   | 示例                                     |
| ---------- | ---------------------- | ---------------------------------------- |
| 领域单元   | 不变量和边界快速反馈   | 金额精度、状态迁移、路由排序、账务平衡   |
| 组件集成   | 服务与真实基础设施协作 | PostgreSQL 事务、outbox、锁、唯一约束    |
| 适配器契约 | 第三方差异标准化       | 签名、错误码、超时、重复回调、沙箱样本   |
| 消费者契约 | API/事件兼容           | 前端和服务对 OpenAPI、事件 schema 的期望 |
| 端到端     | 跨系统关键旅程         | 下单、支付、充值、退款、查询、人工处理   |
| 非功能     | 性能、恢复与安全       | 峰值、故障注入、备份恢复、越权、重放     |

## 必测矩阵

- 0、负数、极大金额、0/2/3 位 exponent、多币种和汇率舍入。
- 同一请求并发 2 次、回调重复 100 次、回调早于同步响应。
- 供应商超时后实际成功、查询先失败后成功、回调乱序。
- 支付成功后进程崩溃、outbox 积压、消费者处理后确认前崩溃。
- 单供应商故障、全供应商不可用、余额不足、限流和维护窗口。
- 部分退款、重复退款、退款失败、拒付和冲正。
- 管理员跨租户/跨角色访问、敏感字段解密、导出和审批绕过。
- 数据库恢复后账本、订单和 outbox 的一致性。

## 准入门槛

- 核心领域分支测试覆盖率目标不低于 90%，但以不变量场景完整为先。
- 所有供应商/支付适配器必须有录制样本和负向签名测试。
- 发布前在沙箱完成至少一次成功、明确失败、未知转人工、自动退款全链路。
- 任何账本不平、重复充值或重复扣款缺陷均阻断发布。
- 生产问题修复必须先补可复现测试，紧急缓解后补齐也需有明确时限。
