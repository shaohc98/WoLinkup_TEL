# 现有原型分析

> 本文分析对象为 `legacy/` 中的早期消费者端和运营后台样本。运营管理后台正式原型 V1.0 已归档，需完成专项精读后另行形成评审结论，本文不自动代表对新版本的评审。

## 资产结论

消费者端原型与运营后台原型都是单文件 HTML，样式、状态和演示数据直接内嵌。两份独立数据脚本均包含 226 个国家/地区、624 个运营商、151 种货币、6 个区域和 16 个热门国家/地区，但文件之间有 608 行差异，部分号码规则、运营商命名、汇率字段和面额算法不同。

因此它们适合作为需求样本，不适合作为唯一事实来源。生产系统需要独立的主数据模型、来源记录、发布流程和版本控制。

## 已覆盖能力

### 消费者端

- 国家/地区搜索、国际区号和号码格式校验。
- 运营商自动识别与人工选择。
- 固定面额和自定义面额、汇率换算、服务费、会员优惠。
- 微信、支付宝和余额支付的确认界面。
- 成功、延迟、维护和失败退款等演示场景。
- 充值记录、登录注册、会员权益、在线客服、协议与隐私政策。

### 运营后台

- 客户、会员和登录日志。
- 充值订单、退款订单和重试处理。
- 产品价格、国家、运营商、汇率与供应商 SKU。
- 供应商健康度、余额、充值和通道信息。
- 微信、支付宝、余额账户、账户充值、资金流水。
- 发票、采购侧对账、活动、优惠券、积分。
- 内容、消息模板、发送记录、客服工单和 FAQ。
- 管理员、角色权限、安全设置、操作审计和全局搜索。

## 关键缺口

| 领域     | 原型现状             | 工程要求                                           |
| -------- | -------------------- | -------------------------------------------------- |
| 订单     | 单个前端对象承载交易 | 拆分业务订单、支付投影、充值尝试、退款单和状态历史 |
| 幂等     | 未体现               | 下单、支付回调、供应商请求、回调和退款均需幂等键   |
| 路由     | 演示选择             | P0 使用人工批准的静态主备路由；动态优化列入 P2     |
| 财务     | 展示余额与流水       | 建立退款预算、供应商资金、业务事实和对账差异处理   |
| 数据     | 两版脚本存在漂移     | 建立主数据来源、草稿、审核、发布和回滚版本         |
| 安全     | 仅有 UI 设置         | 密钥托管、字段加密、脱敏、RBAC/ABAC、审计和风控    |
| 合规     | 示例协议             | 按主体、地区、支付方式和数据跨境路径完成专项评估   |
| 可靠性   | `setTimeout` 模拟    | 使用持久队列、超时任务、补偿、重试策略和人工队列   |
| 可观测性 | 无服务指标           | 统一日志、指标、追踪、业务漏斗和供应商 SLA         |
| 国际化   | 主要为中文/CNY       | 支持 locale、时区、展示币种、结算币种和 RTL 评估   |

## 原型到实现的映射

| 原型能力                 | 归属应用     | 后端责任                                                   |
| ------------------------ | ------------ | ---------------------------------------------------------- |
| 国家、号码、运营商、面额 | 两个消费者端 | `foundation`、`catalog`、`pricing`                         |
| 下单、查询、售后         | 两个消费者端 | `order`、`fulfillment`、`finance`                          |
| 支付与账户余额入口       | 两个消费者端 | Payment Platform + `payment-platform` 防腐层；钱包条件开放 |
| 供应商与 SKU             | 运营后台     | `procurement` + 供应商适配器                               |
| 退款、资金事实和对账     | 运营后台     | `finance` + Payment Platform 投影                          |
| 内容、活动、客户、权限   | 运营后台     | `site`、`marketing`、`customer`、`foundation`              |
| 通知与延迟任务           | `tel-worker` | Outbox/Inbox + pg-boss                                     |

## 需要产品确认的决策

- 国际站首发国家、结算主体、展示币种和支付方式。
- 中国大陆端首期为 H5，小程序列入 P2；App 是否建设仍待确认。
- 用户是否必须登录，游客订单如何查询和申诉。
- 供应商采购是预付、授信还是混合，结算周期与争议机制是什么。
- 失败、超时和错充的责任边界，是否允许人工退款或补充充值。
- 实时汇率来源、锁价时长、加价规则和汇率风险承担方。
- 是否向企业客户开放 API，以及是否从第一阶段支持多租户。
