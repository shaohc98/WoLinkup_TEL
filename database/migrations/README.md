# 迁移顺序

正式迁移按以下序列建设。文件未实现前不得创建空 SQL 伪装为已完成迁移。

| 序号 | 名称                   | 主要内容                           |
| ---- | ---------------------- | ---------------------------------- |
| 0000 | `platform_events`      | Outbox、Inbox、幂等记录和任务基础  |
| 0001 | `foundation_reference` | 国家、币种、时区与参考数据         |
| 0002 | `customer_site`        | 客户、收件号码、站点与渠道         |
| 0003 | `catalog_supplier`     | 运营商、商品、供应商与供应商品     |
| 0004 | `pricing_quote`        | 价格、汇率、费用与报价快照         |
| 0005 | `topup_order`          | 订单、状态迁移与审计事实           |
| 0006 | `payment_integration`  | 外部支付引用、状态投影与事件收件箱 |
| 0007 | `fulfillment`          | 履约尝试、提交、查询与回调         |
| 0008 | `finance_settlement`   | 财务事实、供应商资金与结算投影     |
| 0009 | `refund_service`       | 退款订单、审批、额度预占与结果     |
| 0010 | `risk`                 | 风险规则、决策与人工审核           |
| 0012 | `constraints_indexes`  | 跨表约束、并发保护与性能索引       |

每个迁移必须包含前向验证、兼容窗口和回滚或补偿说明，并在真实 PostgreSQL 上通过集成测试。
